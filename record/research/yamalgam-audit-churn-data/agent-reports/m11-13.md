## 2. Churn evidence

**(a) A fix that became the next audit's finding.** M12 `lsp-didchange-rebuilds-full-document-stages` closed by `660a8a4` ("perf(lsp): batch document snapshot rebuilds"). The diff replaced incremental `syntax.apply(&[edit], config)` with full-text materialization. 20h later M13 RC quoted that exact new code as `lsp-changes-copy-and-rebuild-whole-document`. Re-reported and re-deferred in audits 5, 6, 7. One remediation → four subsequent finding-reports.

**(e) Pure re-verification cost.** Five slugs appear verbatim in all four M13 audits; one in three. 17 of 40 M13 finding-reports (43%) re-report already-deferred work. Closure ledger: "These six findings are the same bounded internal optimization opportunities carried through the previous audits." Audit 7 produced exactly one novel finding — a stale Cargo.toml description.

**(b) Same-defect-class re-finding, one file at a time.** "limit enforced after allocation" class drip-fed across all four M13 audits (`emitter-plain-scalars-use-scratch-buffer` → `emitter-fragment-indent-allocates-before-limit-check` → `json-renderer-allocates-before-output-limit` → `validate-json-bypasses-output-byte-limit` + `emitter-transformed-scalars-allocate-before-output-accounting`, same file/function as the first). Same for "linear scan should be an index" ×4 across M11–M13.

**(c) False positives / reviewer cost.** M12 reviewer-verdicts: 0 disputed, 10 confirmed, 10 adjusted; 8/10 adjustments cosmetic (indentation restoration). No `disputed` disposition anywhere in slice.

**(d) Fixes reverted/redone.** No reverts. Redo happens inside a finding: `lsp-schema-edits-never-invalidate-dependent-validation` took 6 commits, 20 files, 3007+/174−, 3 crates (incl. `yamalgam-resolve/src/retriever/file.rs`), "fifth-round independent review is clean." Audit effort estimate: medium.

**Test-mutation check — negative.** No tests weakened to pass. One test rewrite (`949ee80`, memory:// → file fixtures) was directed by the finding's remediation text but silently deleted the only cross-crate coverage of memory-scheme includes.

- `Audit-Finding:` trailers on all 17 M13 fixes.
- Fixes carry measured proof (3.37s → 15ms; 115,200 → 639 comparisons).
- Cross-crate gates run and reported per fix in some entries; M11 closure ran `just check`, `just test-compliance`, `cargo hack --each-feature`, `cargo machete`.
- Real blockers caught (M13 RC critical: `in-place-rename-overwrites-concurrent-source-change`, real data-loss).

## 4. Root causes
1. Definition of done mandates another audit ("M13 closes only after a fresh full-repository audit confirms…"). Fact.
2. Deferred findings invisible to next auditor → re-derived. Externally-blocked deferral never recurred because not derivable from source. Inference, strong.
3. Findings located, not classed — no sibling sweep. Fact.
4. Effort estimates ignore cross-crate blast radius. Fact.
5. Auditor scans its own output: recon shows HTML 22.9%, Markdown 27.3% of corpus; tree grew 232,606 → 247,569 lines in one audit day. Fact.
6. Reviewer calibrated on transcription, not truth. Fact.
7. AGENTS.md defines ledger but not verification gates. Fact.

## 5. Recommendations
Audit side: ingest prior ledgers → `carried_forward:` block excluded from counts/narrative; class-sweep phase (one finding, N locations); effort from blast radius (reverse-dep fan-out); exclude `record/audits/**` and `*.html` from recon; retarget reviewer to claim falsification, extract snippets by byte range mechanically; explicit release gate verdict instead of "close after another clean audit."
Remediation side: verification block per `fixed` entry (exact gate commands + results); blast-radius line (crates touched vs named); `superseded-by` disposition; forbid silent test-fixture rewrites (state coverage lost); cap in-finding iteration at 3 commits → design review.
